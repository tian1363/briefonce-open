# BriefOnce 前端设计规范

> 基于 2026-09-03 当前 React 实现整理。本文是新增与重构界面的执行标准；`brand-spec.md` 保留为品牌摘要。

## 1. 产品体验原则

BriefOnce 是持续工作的创作 Agent，不是传统数据后台。界面应让用户始终看清三件事：当前上下文、Agent 正在做什么、下一步能做什么。

1. **结果优先**：先展示结论或产物，再展示行动摘要；系统提示词、原始 JSON、内部推理默认不展示。
2. **真实主动**：Agent 状态来自真实模型与工具事件，不使用写死的阶段或假进度。
3. **信息渐进**：高频信息直接展示，参数、证据、完整提示词和技术详情折叠后查看。
4. **素材可见**：图片、视频和生成结果必须有封面；引用素材用缩略图、名称和来源建立对应关系。
5. **少线条分层**：优先使用留白、背景差、排版和轻阴影分层；边框只用于输入、选择、聚焦、危险操作和必要分区。
6. **上下文稳定**：导航、对话上下文和输入框不随长内容移动；只让内容列表滚动。

### 2.2 使用规则

- 一个页面只使用珊瑚红作为产品品牌强调色，不新增紫色或蓝色品牌状态。
- 绿色仅表示成功，橙色仅表示警告，红色仅表示错误或危险操作；不可拿语义色做装饰。
- 文字必须使用三级语义色，不用降低透明度替代弱文字。
- 大面积内容背景保持暖白；珊瑚红只用于面积较小的行动和状态反馈。
- 新代码优先使用语义 Token，不直接写十六进制色值。

## 3. 字体与信息层级

字体栈：`Inter`、`Noto Sans SC`、系统无衬线字体。代码与原始参数使用 `JetBrains Mono` 等宽字体。

| 层级 | 建议字号 | 字重 | 用途 |
| --- | ---: | ---: | --- |
| 页面主标题 | 32–40px | 600–700 | 页面唯一主标题 |
| 区块标题 | 24px | 600 | 主要内容区标题 |
| 小节标题 | 16–18px | 600 | 卡片或表单小节 |
| 正文 | 14px | 400 | 默认内容 |
| 标签/按钮/辅助正文 | 12–13px | 500–600 | 控件、状态、说明 |
| 元数据 | 10–11px | 400 | 时间、费用、来源等 |

- 中文正文行高使用 1.5–1.65；长脚本和 Markdown 使用 1.65–1.75。
- 标题通过字号、字重和上下间距建立层级，不用边框包住标题。
- 页面只保留一个 `h1`；列表项标题不模拟大标题。
- 文案简短具体：使用“处理中”“生成视频”“添加素材”，避免“助手处理中”等冗余表达。

## 4. 间距、圆角与阴影

### 4.1 间距

使用 8px 基础网格：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64`。

- 页面桌面端顶部与左右留白默认 48px。
- 页面区块间距 24–32px；区块内部 12–16px；紧密控件间距 4–8px。
- 同级页面主标题的基线和顶部间距必须一致。

### 4.2 圆角

- 小控件：6–8px。
- 菜单项、输入框：8–12px。
- 内容卡片：12–18px。
- 主输入框与重要浮层：20–24px。
- 胶囊仅用于状态和紧凑筛选，不用于普通按钮。

### 4.3 阴影

- 常规内容区默认无阴影。
- 浮层、悬浮入口、聚焦输入框才使用轻阴影。
- 阴影必须低对比、暖黑色；不得同时使用粗边框和重阴影。

## 5. 页面框架与滚动

### 5.1 主导航

- 桌面默认 68px 图标栏，展开宽度 224px。
- 展开/收起不覆盖内容，不保留无意义竖条。
- 导航项高度约 42px；图标 19px；激活态用淡珊瑚底和深珊瑚文字。
- 移动端改为底部 66px 导航，隐藏桌面账户详情和低频入口。

### 5.2 内容容器

- 应用外壳固定为视口高度，页面主体 `min-height: 0`。
- 长内容只在本区域滚动：对话消息、历史列表、Skill 正文、素材预览、开发者详情。
- 固定区域包括主导航、对话上下文栏、输入框和关键操作。
- 常规页面内容最大宽度建议 1060–1240px；阅读正文建议不超过 920px。

### 5.3 响应式

- `≤1000px`：隐藏非关键第三栏，保留主要任务。
- `≤700–760px`：多栏变单栏，页面边距降至 18–24px。
- `≤560px`：启用底部导航；所有浮层宽度不超过 `94vw`。
- 100% 浏览器缩放下必须看到主要输入与提交操作；长内容不得撑高整个应用框架。

## 6. 通用组件

### 6.1 按钮

- 主按钮：珊瑚实底、白字，只承载每一区域唯一的主要行动。
- 次按钮：暖白或透明底、弱边框；Hover 使用暖灰背景。
- 图标按钮：至少 36×36px，必须有 `aria-label` 和悬停说明。
- 危险操作：默认低调，确认阶段才强化；删除必须二次确认。
- 禁用态保留文案可读性，并明确不可点击。

### 6.2 输入与选择

- 常规高度 36–48px；输入框聚焦使用珊瑚边框和浅色焦点环。
- 长文本框应占据主要视觉空间；视频分辨率、时长、比例、声音等参数退居次级工具栏。
- 同一功能只保留一个入口，例如素材上传不再同时出现“加号”和“素材”。
- 错误信息使用用户可理解的中文结论与恢复动作，不直接暴露服务端 JSON、状态码或密钥片段。

### 6.3 卡片与列表

- 可点击列表优先使用无边框行，Hover/选中后才出现背景或强调线。
- 卡片只在内容本身需要独立边界时使用；不要为每一段文字套卡片。
- 标题、摘要、状态、时间顺序固定；时间必须完整显示到分钟，必要时到秒。
- 超长标题单行省略，完整内容通过详情或悬停获得。

### 6.4 浮层与预览

- 浮层最大高度不超过 `92vh`，结构为固定头部、可滚动正文、固定操作区。
- Skill 预览顺序固定：来源/权限、名称、描述、元数据、正文、行动。
- 系统 Skill 只读；用户 Skill 可编辑、删除。
- 图片和视频使用暗色预览舞台与 `contain`，不能裁掉主体。
- 单张图片下载统一使用图片右上角的悬浮按钮：鼠标移到图片或键盘聚焦时显示，触屏设备直接显示。点击下载不触发图片预览、选择或画布拖动；长图滚动时按钮保持可见。批量图片包使用单独的导出入口。

## 7. 对话与 Agent 反馈

### 7.1 对话结构

- 用户消息右对齐，使用淡珊瑚背景；助手结果左对齐，以正文为主，减少外框。
- 产品资料位于对话上下文栏；从创意空间进入时锁定，修改入口返回空间。
- 历史对话收起后使用不遮挡正文的悬浮/内联图标，不保留空竖栏。
- 输入框固定在底部，内容区域独立滚动；工具入口位于输入框底部一行。

### 7.2 Agent 运行态

- 用户发送后立即显示“处理中”。
- 只展示真实事件：判断下一步、检索资料、调用 Skill、生成视频、整理结果。
- 当前动作使用珊瑚动态点；完成使用低饱和绿色；失败使用警告/错误色。
- 运行时展开行动摘要；完成后默认收起为“已完成 · N 个步骤”。
- 不展示隐藏思维链。可解释信息只写简短决策摘要、行动和结果。
- 历史轮次保留各自的行动摘要，不能只保留最后一轮。

### 7.3 输出内容

- 先给结果摘要，再给可执行内容；技术过程默认省略。
- 引用产品素材时展示小封面、素材名称和 CID/来源关系。
- 视频结果必须包含可预览封面、状态、生成参数、费用和三行提示词摘要；详情中允许继续编辑或复用。

## 8. 状态、反馈与可访问性

- 所有异步操作具备：即时开始反馈、进行中状态、成功结果、失败恢复动作。
- 空状态必须告诉用户“现在没有什么”和“下一步可以做什么”。
- 键盘焦点使用 2px 珊瑚焦点环；不可只依赖颜色表示选中或错误。
- 交互目标桌面端至少 36px，移动端至少 44px。
- 图标按钮必须有可访问名称；表单必须有真实标签；动态状态使用 `aria-live`。
- 动画以 150–250ms 为主；持续加载动画必须支持 `prefers-reduced-motion` 降级。
- 需要在 200% 缩放、键盘操作、屏幕阅读器和颜色对比工具中单独验证；视觉检查不能替代这些测试。

## 9. 当前实现中的设计债务

以下属于历史样式，不应作为新增界面的参考：

1. 部分聊天引用、用户消息和焦点阴影仍包含紫色 `rgba(139, 78, 239, …)` / `rgba(132, 78, 239, …)`，应统一替换为珊瑚语义 Token。
2. 登录页仍有蓝色径向背景，与“单一暖色品牌强调”原则不一致。
3. 部分页面直接写 `8/9/10/14/18/20/24/26px` 圆角，没有使用 Token，导致同级组件外观漂移。
4. 页面标题同时存在 32、40、42、48px 多套规则，应收敛为“标准页面 32–40px、营销首页 40–48px”两档。
5. `styles.css` 中存在大量页面级压缩写法和重复选择器，后续应拆分为 `layout / components / features`，并禁止新增无语义硬编码色。
6. 目前字体依赖 Google Fonts；网络不可用时会回退。正式部署应自托管字体以保证中英文一致性。

## 10. 新界面验收清单

- [ ] 是否使用现有语义 Token，且没有新增紫/蓝品牌色？
- [ ] 是否只有一个明确主操作？
- [ ] 是否通过留白和背景分层，而非给每块内容加边框？
- [ ] 页面标题顶部是否与其他一级页面一致？
- [ ] 长内容是否只让局部区域滚动，主要操作是否始终可见？
- [ ] 加载步骤是否来自真实运行事件？
- [ ] 错误是否转成用户能理解并能恢复的中文信息？
- [ ] 图片/视频是否有封面、预览、来源与删除能力？
- [ ] 360px、768px、1280px 宽度下是否可完成主任务？
- [ ] 100% 与 200% 缩放、键盘焦点、减少动态效果是否可用？

## 11. 画布节点下拉框规范（2026-10-15）

- 节点内统一使用 `web/app/src/CanvasSelect.jsx`，禁止原生 `<select>`。包括模型、画幅、分辨率、商品、模特、参考图及姿势筛选；共享表单在节点内使用时同样遵守。
- 浮层通过 Portal 挂载到页面顶层（原生模态弹窗中挂载到该 dialog 顶层，避免被 top layer 遮挡或变为不可交互），使用视口坐标定位，不被节点裁切、不随画布缩放；靠近视口边缘时调整展开方向和位置。
- 控件及浮层阻止画布拖动、平移和滚轮缩放；长列表在浮层内滚动，外层滚动时关闭，避免位置错位。
- 使用现有产品语义色、圆角和字体；选中项有标记，悬停、键盘焦点及禁用状态清晰。
- 支持方向键、Enter / 空格、Escape、Tab 和点击外部关闭，并提供字段名称、展开状态、选项选中状态。
- 验收覆盖缩放、拖动、边缘位置、长列表和键盘操作。

- 画布节点只展示姿势库入口、已选数量与已选缩略图；完整搜索、筛选和分页放入独立弹窗。弹窗不随画布缩放，支持 Escape 关闭、焦点约束及关闭后回到入口。

- 图片素材选择不能仅展示文件名：下拉选项和已选值均须提供真实缩略图封面与名称，图片等比完整显示；空选项不放占位封面。此规则适用于商品、结构参考、视觉参考及模特图片。

## 12. 规范来源

- 颜色、字体、间距及基础 Token：`web/app/src/design-system/colors_and_type.css`
- 当前组件和页面实现：`web/app/src/styles.css`、`web/app/src/App.jsx`
- 品牌摘要：`brand-spec.md`
- 固定对话输入框回归基线：`design-qa.md`

### 画布节点的长名称约束

节点内容的 Grid 列使用 `minmax(0, 1fr)`，直接子元素及表单分组必须可收缩（`min-width: 0`），控件不得被文件名撑宽。商品选择摘要、素材名称等单行文本在节点可用宽度内省略，完整名称通过悬停标题或预览查看。不得仅依赖节点外层 `overflow: hidden` 截断溢出控件；验收需使用超长中文名及连续无空格文件名，检查控件边界与节点内边距。

### 素材缩略图的次要操作

素材列表默认突出图片与名称。移除等次要操作默认隐藏，仅在鼠标悬停对应图片卡片时出现，不要在所有缩略图上常驻叉号。按钮独立于图片预览入口，点击只执行该项操作，不触发预览。对仅解除关联、保留历史与原文件的移除操作，单击立即生效，不增加确认弹窗；文案与提示须明确「从产品资料移除」。请求期间禁用重复操作。

键盘焦点进入卡片时也需显示操作按钮，并提供清晰的无障碍名称；不支持 hover 的触屏设备保持按钮可见。隐藏按钮不能遮挡或截获图片点击。破坏性永久删除不套用此单击移除规则。

### 外部账号连接状态
- 创意解读首次进入显示未连接，不自动检查；用户主动连接或检查后，依据服务端真实状态显示已连接、需要登录、连接助手不可用或未配置，禁止只凭本地布尔标记显示已连接。
- 扫码提示保留待处理输入；会话失效提供重新连接，连接成功继续原任务。二维码到期提供明确重新获取入口，退出后不丢失当前账号的链接草稿。
- 来源读取与 AI 分析分成两步，展示实际内容覆盖；只有标题时不得将按钮或结果标成完整分析成功。

### 工作流场景操作入口的一致性

- 各场景共享画布顶部的场景切换、产品资料和作品库。不得在画布外重复增加某个场景专属的操作栏或主按钮。
- 选素材、选模板参考图、调整参数、策划与生成等场景操作放入对应节点。弹窗由节点按钮打开，选中结果、预览及取消选择仍在该节点内呈现。
- 同一操作保留一个主要入口。新增场景或入口时，要与其他场景对照检查按钮位置、节点层级和选中反馈，避免同样功能在画布内外重复出现。

- 工作流页面优先让画布占满可用屏幕，保留紧凑的返回栏，避免四周大留白。首次进入、切换场景与重置视图时，按全部节点的实际尺寸适配总览；顶部工具栏须预留独立安全区域，不能遮挡节点。用户开始拖动、缩放或编辑后，不因后台数据刷新而自动跳动视角。

- 叠图入口必须为旋转后的缩略图预留完整宽度，图片不能侵入标题、说明或箭头区域。场景切换入口的图标沿用工具箱同一场景图标，并与文字一起保留选中和聚焦状态。

### 勾选项组件与样式隔离
- 新增勾选项复用 CanvasToggle 自定义组件，保持 18px 勾选框、8px 文字间距、左侧紧凑对齐和清晰禁用状态；不得使用会被普通输入框样式撑满宽度的原生勾选框。
- 输入框通用宽度、内边距和最小高度规则必须排除 checkbox/radio；组件行宽与勾选框尺寸分开定义。没有可选内容时不显示已勾选状态。
