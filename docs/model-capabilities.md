# 模型能力、BYOK 与托管积分

> 最近维护：2026-10-14 · 设置入口：产品前台左侧“设置” · 当前支持账号级配置隔离。

BriefOnce 将模型配置按业务能力隔离，避免用户为图片或视频更换模型时影响脚本生成。

## 章鱼哥图片接入

图片生成和编辑支持按能力配置图片模型，并按型号校验比例、尺寸与参考图格式。用户可在对应入口选择已启用的型号。图片与视频使用各自的服务配置，接口要求以当前模型目录为准。

下方 Qwen 规则适用于保留的百炼配置，不能用于新供应商。

## 配置模式

- `managed`：使用管理员在运营后台配置的平台模型与 API Key（共享 Key 可由环境变量提供）。试用账号只使用积分，在每次付费调用前检查余额、试用期限和每日上限。
- `byok`：使用当前部署中用户保存的 API Key，适合私有部署和用户自行承担模型费用。

API Key 只由后端保存和读取，设置接口只返回掩码，并受登录 Session 保护。管理员的平台模型按能力集中配置；试用账号继承这些配置且只使用积分。管理员自己的个人配置按能力保存，可选择个人 Key 或平台配置。配置 `SCRIPT_AGENT_ENCRYPTION_KEY` 后，API Key 使用 AES-256-GCM 加密保存；旧明文记录会在启动时自动迁移。

## 能力路由

| capability | 功能 | 默认推荐模型 |
| --- | --- | --- |
| `text` | 对话、脚本、裂变、检查 | `qwen3.8-flash` |
| `multimodal` | 图片和视频素材分析 | `qwen3.8-omni-flash` |
| `image_generation` | 分镜、封面、场景图 | `qwen-image-2.0` |
| `image_edit` | 局部编辑和换背景 | `qwen-image-2.0`（须核对当前工作空间可用模型） |
| `video_generation` | 文生视频和参考素材视频 | 章鱼哥 `seedance-2.0` / `seedance-2.0-mini` / `minimax-h3` / `minimax-h3-max` |

图片生成和编辑也需要当前百炼工作空间的 `.../api/v1/services/aigc/multimodal-generation/generation` 地址及同地域 Key。模型名称以该工作空间 `GET /api/v1/models?model=...` 的返回为准；如果模型不存在，先在管理员的平台模型配置中切换可用模型，再重新提交批次。图片批次遇到模型不可用或限流时停止后续请求，未生成的项目会显示失败原因。
| `embedding` | 多模态素材检索 | `qwen3-vl-embedding` |

当前生成客户端会根据输入内容自动路由：纯文本进入 `text`，包含图片或视频的请求进入 `multimodal`。图片、图片编辑、视频和向量能力保留独立配置，供对应生成任务使用。

参考视频脚本和开头复刻先读取时长、候选切镜与音轨是否存在，再将素材和拆解提示词送入多模态模型。默认推荐百炼 `qwen3.8-omni-flash`，由音视频模型核对画面、旁白和 BGM。选择百炼 `kimi-k2.6` 时直接输入视频进行画面拆解，选择 `kimi-k3` 时将最多 72 张带时间戳的抽帧图片送给 K3；两者均用同一百炼 Key 调用 Omni 单独核对音轨。若音轨调用不可用，旁白和 BGM 标为“未确认”，不能从字幕推断口播。百炼 K3 不接收视频文件。Kimi 模型需使用开通该模型的百炼业务空间对应地域的端点。可用 `SCRIPT_AGENT_REFERENCE_OMNI_MODEL` 覆盖音轨核对的 Omni 型号，设为 `off` 关闭该路径。分镜时间是模型依据采样帧的估计，仍需人工复核。

首次打开产品会引导选择文本与多模态模型，也可以稍后在设置中完成。UI 文本推荐 `qwen3.8-flash`，未保存配置时优先使用该推荐值；服务端环境变量 `SCRIPT_AGENT_MODEL` 仍可显式覆盖。

## 产品化约束

- 前端不得取得完整 API Key。
- BYOK 配置没有 Key 时应显示未连接，调用不得自动消耗平台额度。
- 新账号没有 BYOK 配置时不得回退到服务端的托管 Key。
- 托管模式需要 `SCRIPT_AGENT_ALLOW_MANAGED_MODE=true` 和平台共享百炼 Key；共享 Key 可以保存在运营后台，或由 `DASHSCOPE_API_KEY` 提供。管理员还需逐项配置平台模型，视频使用独立章鱼哥 Key 和 `/v1/videos` 接口；语音识别也需单独配置。普通试用用户不编辑模型配置，只查看积分。环境配置见[部署说明](managed-deployment.md)。
- 图片和视频按成功生成张数或秒数记录用量；异步任务应记录创建、处理中、成功和失败状态。
- 模型目录由产品控制，用户可在对应能力内切换，不允许把文本模型误配到视频生成能力。

## 2026-10-15 视频供应商迁移

- 新建视频只接入章鱼哥：`seedance-2.0`、`seedance-2.0-mini`、`minimax-h3`、`minimax-h3-max`。旧 Wan 不再出现在模型选项中，也不可提交或重试；历史作品文件保留。
- 采用异步 `POST https://zexapi.com/v1/videos`、`GET /v1/videos/{id}`。本地素材使用 multipart 中重复的 `input_reference` 上传；`seconds` 为字符串。图片、视频合计最多 9 项。供应商还支持音频参考，但当前产品资料上传入口尚未提供音频文件。
- 四款均支持 4–15 秒、16:9 / 9:16 / 1:1 / 4:3 / 3:4 / 21:9。Seedance 支持首帧和首尾帧，MiniMax 使用普通参考内容。首尾帧不能与其他参考混用。
- 分辨率默认不传；720p、1080p 是待供应商确认并在后台启用的档位，不声称账号已开放。声音要求及负面描述写入提示词，不发送文档未定义的 `audio`、`negative_prompt` 等参数，不保证音轨控制效果。
- 供应商价格页 https://otuapp.com/#/pricing 当前需要登录；用户决定稍后提供报价。全部视频价格默认停用，未定价不扣费、不提交。不可套用旧 Wan 单价。自有 Key 模式由供应商结算，产品积分为零。
- 供应商 Key 独立加密保存。迁移仅在旧视频配置下复用已经保存的同供应商图片 Key；绝不复用百炼 Key。新任务保存加密接口配置快照，轮询和服务重启使用该快照，后台修改不会串用账号。
- 已提交但状态不确定的旧供应商任务需人工核对；历史数据不删除。新协议明确失败退回积分，网络不确定状态保留原有核对逻辑。
